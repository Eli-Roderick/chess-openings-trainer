# Rules for AI build agents

- Read `docs/plan/README.md` and your phase file before writing code. The plan is the spec; if the plan is ambiguous, pick the reasonable default, write it in `docs/DECISIONS.md`, and continue.
- Commands: `flutter pub get`; `dart run build_runner build -d` (in the root and in `packages/chess_core`); `dart format .`; `flutter analyze`; `dart test` (inside packages; in `packages/uci_engine` use `dart test --exclude-tags engine` unless the Stockfish binary is fetched, and `dart test --tags engine` after fetching it); `flutter test`; `xvfb-run -a flutter test integration_test/app_test.dart -d linux` (one file per invocation, D-62) and `xvfb-run -a flutter drive --profile -d linux --driver=test_driver/integration_test.dart --target=integration_test/cold_start_test.dart`; `dart run tool/validate_pgn.dart --colour white <file.pgn>`; coverage: `(cd packages/chess_core && dart test --coverage=coverage)` then `dart run tool/check_coverage.dart --package packages/chess_core --min 90 lib` (and `--min 95 lib/src/training`); `dart run tool/fetch_engines.dart --platform <linux|android|windows>`.
- Definition of done for any PR: analyzer clean (no infos), formatted, all tests green, new logic has tests, `docs/PROGRESS.md` updated, generated files committed, no TODOs without an issue reference.
- Never: put chess/scoring/scheduling logic in widgets; use `print` (use `logging`); add a package not in `docs/DEPENDENCIES.md` without a DECISIONS entry; make network calls outside `features/sync`; block the UI isolate with parsing or DB work; use real time or unseeded randomness in logic (inject `Clock`/`Rng`); edit generated files by hand.
- Database changes: bump `schemaVersion`, write a migration, add a migration test (drift `SchemaVerifier`, schemas exported to `drift_schemas/`): `dart run drift_dev make-migrations`, then `dart run drift_dev schema generate drift_schemas/app_database/ test/drift/app_database/generated/`. Record runs through `StatsService.recordRun`; after a re-import call `StatsService.rebuildRepertoire`.
- UI strings go in `app_en.arb`.
- Keep PRs to one phase (or one sub-phase); title `P<nn>: <name>`.
- Constructors use the Dart 3.13 primary-name syntax, because very_good_analysis enables `unnecessary_type_name_in_constructor` and CI runs `flutter analyze --fatal-infos`: write `const new({super.key});`, `new(this.x);`, `new named() : ...;` and `factory fromJson(Map<String, dynamic> json) => ...;`, never `const MyWidget({super.key});`, `MyModel.named()` or `factory MyModel.fromJson(...)`. `dart fix --apply` converts old-style constructors. freezed classes: `const factory({...}) = _Name;` (unnamed factories cannot be called `new`), `factory fromJson(...) => _$NameFromJson(json);` and `const new _();` for the private constructor that enables getters.
- Flutter is pinned in `.flutter-version` (CI reads it). Upgrading Flutter is a DECISIONS entry, not a side effect.
