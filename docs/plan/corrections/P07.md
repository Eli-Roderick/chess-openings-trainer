# P07 corrections (from the P07 build thread, 2026-10-06)

1. **Opponent delay origin.** 01 §7.4 counts the opponent delay "from the end of the user's move animation". A dropped piece does not animate (chessground skips the dragged piece), so the drill needs to know how the move was made: `RepertoireBoard.onUserMove` now reports `viaDrag`. Delay = opponent delay, plus the board animation time for tap-tap moves. (D-86)
2. **Drill latency.** "User drop → opponent animation start" includes the opponent delay (250 ms by default), so p95 ≤ 300 ms leaves 50 ms for the app. Measured in profile mode on Linux: p50 252 ms, p95 262 ms over 26 replies.
3. **Start-from default.** P07 task 7 asks for a stored start-from default before the mode sheet (P08). Added `AppSettings.startFromBranchPoint` (default off); P08's mode sheet remembers the choice per repertoire.
4. **Read-only grade access.** `RunBuilder.ply()` creates a grader on first use, so the drill cannot use it to read grades (an empty grader for a future ply would later reject the correct move). chess_core gained `RunBuilder.gradeAt(ply)` and `RunBuilder.grades`.
5. **"Not your repertoire move".** Shown for 2 s only when the check says not comparable and the user is still at that ply; not after a hint turned a comparable move into 0.
6. **Streak in flow 1.** 10-testing §3 flow 1 ends with "streak shows 1"; the streak arrives in P10. The flow checks the end bar, auto-advance and 100 % line accuracy now; the streak assertion is added in P10.
