# P13 corrections (from the P13 build thread, 2026-10-06)

1. **Export logs is one text file, not a zip.** 10-testing §6 says "zip of log files". The log is at most three rotated files of 1 MB; Diagnostics → Export logs saves them oldest first as one `repertoire-trainer-logs-YYYY-MM-DD.txt` through the save dialog. No new runtime dependency (`archive` stays a tool-only dev dependency), and the file opens anywhere. (D-115)
2. **Diagnostics items from §6 that no earlier phase built.** Import benchmark, the Database section (file size, rows per table, last derivation) and the Frames budget from the display refresh rate with "% over budget" and worst raster are built here. (D-115)
3. **Frame budget in CI covers builds only.** The CI runner rasterizes in software (D-71), so the new drill check (20 lines, < 1 % of frames over budget) asserts build times; raster times are logged and the "worst raster < 2x budget" criterion is checked on devices.
4. **Board rebuilds measured, not traced.** Task 1 suggests `debugProfileBuildsEnabled`; the profile-mode drag and drill scripts already measure every frame's build time in AOT (worst build 12-13 ms, mean 2-3 ms at 60 Hz), so no rebuild problem needed tracing and nothing was changed.
5. **App name unchanged.** "Final app name decision with Eli": no decision was given in this thread, so the working name stays. Renaming is a find-and-replace of "Repertoire Trainer" and `repertoire_trainer` (keep the Android `applicationId`, or installed data does not carry over). (D-110)
6. **`.pgn` MIME types.** File managers report `.pgn` as `application/x-chess-pgn`, `application/vnd.chess-pgn`, `text/plain` or `application/octet-stream`; the VIEW filter takes all four, and the SEND filter makes the app a share target. Shared content over 20 MB is refused. (D-111)
7. **`FileService.saveText` takes an extension.** It was PGN-only; logs need `.txt`. Default stays `pgn`.
8. **Device-only acceptance criteria.** Cold start, frames and raster on the phone, the 1,000-line import on the phone, stats with Eli's real data and a week without errors in the logs can only be measured on Eli's devices; the Linux AOT numbers are in D-117 and the device checklist stays open.
