# P10 corrections (from the P10 build thread, 2026-10-06)

1. **Most-missed moves need a cache.** Task 1 computes most-missed plies with SQL over `move_grades`. With 20k runs (about 120k grades) the grouped join alone takes 170-280 ms on Linux, so the stats screen opened in 749 ms against the 300 ms target. A derived `ply_stats` cache (repertoire, move sequence, ply → attempts, misses over completed runs) is kept by `StatsService.recordRun` and rebuilt by `rebuildRepertoire`, like `line_stats`. Schema version 2 adds it with a migration that fills it from the stored grades. Covering indexes on `runs` serve the daily aggregates, run count and line keys. The screen now opens in about 200 ms with 20k runs (profile build). (D-101)
2. **What a miss is.** §11.4 says "missed 4 of 6" without defining a miss. A miss is a wrong first attempt or a hint; a comparable move (half credit) is not a miss. Attempts count graded plies of completed runs.
3. **Moving average.** §11.2 asks for a 7-day moving average without a formula. It is pooled: credit over graded moves of the 7 calendar days ending on that day, so a busy day weighs more than a one-line day, consistent with the move-weighted daily accuracy (04 §2.4). Days without runs are gaps in the daily series.
4. **Archived labels.** Archived keys are not in the tree, so their labels come from the run's moves (the last four plies, like current labels, without the PGN prefix).
5. **Line list.** "Show all" is a new route `/repertoire/:id/stats/lines` (01 §2 lists only the line detail route).
6. **Placeholder screen removed.** With Stats and Line detail built, nothing uses the P04 placeholder screen; it and its strings are gone.
