# P03 corrections (from the P03 build thread, 2026-10-06)

1. **Database location.** `drift_flutter`'s default directory is the user's *Documents* folder (missing on a headless Linux runner, and the wrong place on Windows). The database lives in the app support directory (`getApplicationSupportDirectory()`), like the logs. Caught by the Linux integration test, which now waits for `repertoire.sqlite` to appear. (D-53)
2. **Node inserts.** drift's `batch` executes one statement per row; for a 1,000 × 16 synthetic repertoire (3,863 nodes) that was 100-240 ms for the nodes alone, close to the 300 ms target. Nodes and lines are inserted with multi-row `INSERT` statements (50 rows each); a whole `create` takes about 85-150 ms. (D-54)
3. **Home order.** 01 §4 says "sorted by last trained (never trained last, by creation date)" without a direction for the creation date. Never-trained repertoires are newest first. (D-55)
4. **Re-import and stats.** `RepertoireRepository.reimport` writes the new version and returns the diff; the caller then runs `StatsService.rebuildRepertoire` (repositories never call each other). Runs are recorded through `StatsService.recordRun`, which stores the run and re-derives the affected lines. (D-56)
5. **Migration scaffold.** With one schema version, `drift_dev make-migrations` only exports `drift_schemas/app_database/drift_schema_v1.json`. The scaffold test (`test/drift/app_database/migration_test.dart`) validates the database against the exported v1 schema with `SchemaVerifier`; later phases add upgrade tests per version. (D-60)
