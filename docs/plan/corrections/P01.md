# P01 corrections (from the P01 build thread, 2026-10-06)

1. **PGN reading.** 07 §5.1 said to parse with dartchess `PgnGame.parseMultiGamePgn`. That parser skips invalid tokens silently (no way to produce `E-PARSE`) and splits games with the regex `\n\s+(?=\[)`, which cuts a game in two at an indented comment line starting with `[%`. `chess_core` has its own strict reader (`pgn/pgn_reader.dart`); dartchess still does legality, canonical SAN and FEN. 07 §5.1 updated. (D-36)
2. **Malformed comments.** 07 §4 step 4 flagged any comment without a text tag that contains `[%` as malformed, so `{[%clk 0:05:00]}` or `{[%cal Gc4f7]}` alone was `W-MALFORMED`. Now malformed means a tag that is not well formed remains after removing all well-formed tags. 07 §4 updated. (D-37)
3. **Ignored variation-start comment.** 07 §2 said "ignored (info)" without a code. Added `I-COMMENT-BEFORE-IGNORED` to the §6 table. (D-38)
4. **W-CONFLICT** compares parsed comments, so the same text differing only in `%clk`/`%eval` or whitespace is not a conflict (lichess chapters repeat moves with different clock tags). (D-39)
5. **Import entry point.** 03 §6 named `RepertoireTree.fromPgn`; P01 task 6 names `importPgn(text, side)`. Implemented `importPgn` plus `importPgnBytes` (encoding detection needs bytes); 03 §6 updated. (D-41)
6. **Constructor syntax.** As in P00 correction 3: `new(...)`, `const new(...)`, `new named(...)`, `factory fromJson(...)`. Enum constructors are written `new(...)` without `const` (lint `unnecessary_const_in_enum_constructor`).
