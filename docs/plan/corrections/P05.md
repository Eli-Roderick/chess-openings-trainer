# P05 corrections (from the P05 build thread, 2026-10-06)

1. **Sounds.** lila's "standard" set is AGPL-3.0-or-later (it is not among the exceptions in lila's `COPYING.md`), which GPL-3.0 §13 allows this app to include. The set has no castle, line-complete, deviation or hint sound, and its `Check.ogg` is a symlink to `Silence.ogg`. Mapping: move, check and castle → `Move`; capture → `Capture`; error → `Error`; line complete → `Confirmation`; deviation → `GenericNotify`; hint → `Select`. OGG only: flutter_soloud decodes OGG on Android, Windows and Linux, so no WAV fallback is needed. (D-74)
2. **Frame budget in CI.** The task says "no frames over budget in the Diagnostics frame stats during a 30 s interaction script". The GitHub Linux runner has no GPU; Flutter rasterizes in software (llvmpipe) at 40-70 ms per frame whatever the app draws, so raster time cannot meet 16.7 ms there. The script asserts the UI thread instead: builds over one 60 Hz frame (16.667 ms). On a 4-core VM llvmpipe's worker threads starve the UI thread and cause random 17-21 ms builds, so CI runs llvmpipe single-threaded (`LP_NUM_THREADS=1`). The first navigation after opening Browse costs about 30 ms once (first-use work), so the script warms up with one Forward/Back before measuring. At most one slow build in 30 s is tolerated for VM scheduling noise; measured locally: 0 of about 400 frames, worst 15.5 ms, mean 1.6 ms. Raster time is logged, not asserted; devices are covered by the P05 device checklist. (D-71)
3. **Jank budget.** `FrameStats.jankBudget` was 16 ms; one 60 Hz frame is 16.667 ms. FrameStats now also counts slow builds and slow rasters separately.
4. **Move list virtualization.** A `ListView.builder` of wrapped, variable-height rows builds every row between the top and a far target when it jumps (1,929 of about 5,000 rows to reveal a deep node). Rows are split into fixed-height lines that fit the width (move widths estimated from their length after one text measurement), so the list uses `itemExtent` and revealing the current move builds only what is visible. (D-75)
5. **Piece image precaching.** chessground paints pieces from its own `ChessgroundImages` cache, not Flutter's image cache, so "precache the active piece set" is `ChessgroundImages.instance.loadAll` (clearing the previous set on a change).
6. **Rebuilds.** The app widget watched every setting, so any settings change rebuilt `MaterialApp`; it now selects the theme mode only. The board watches only `boardSettingsProvider` (equal `ChessboardSettings` values do not notify).
7. **Profile test file.** `integration_test/cold_start_test.dart` (P04) is now `integration_test/profile_test.dart` and holds both profile-mode budgets.
