# P08 corrections (from the P08 build thread, 2026-10-06)

1. **Start-from default.** P07 added the global `AppSettings.startFromBranchPoint`; P08 task 2 makes the choice per repertoire (`repertoires.drill_start_from`). The two had to be reconciled: a repertoire that has never been trained (`last_mode` null) uses the global setting, afterwards its own stored choice; a `from=` route parameter overrides both. (D-91)
2. **SRS daily review cap across repertoires.** 04 §5.2 defines the cap per day but not per repertoire. It counts SRS reviews (04 §5.2 definition) on the training day across all repertoires, so several repertoires cannot multiply the daily load. (D-93)
3. **Pick after save.** A pick reads live `line_stats`. The previous run is stored in the background (P07 D-88), so a quick Next line could pick from stale stats (a just-failed SRS line not yet due today). The controller awaits the pending save before every pick. (D-92)
4. **Same route, other mode.** go_router keeps the page when only the query changes (`/repertoire/<id>/train?mode=weak` → `?mode=random`), so the old drill (its controller and state) stayed on screen. The drill page is keyed by its full URI. (D-96)
5. **Stale "today".** `todayProvider` was computed once, so an app left open past the day start kept yesterday's due counts and SRS review count. It now recomputes at the next day start (system clock only; test clocks are advanced by hand), and the drill computes the day from the clock at every pick. (D-96)
6. **Integration flow 9 timing.** The flow runs on a fixed fake clock; two runs finished at the same instant replay in run-id order, which is random. The flow advances the clock a minute between runs. Runs in real use cannot tie in a way that matters (one line at a time, millisecond timestamps).
